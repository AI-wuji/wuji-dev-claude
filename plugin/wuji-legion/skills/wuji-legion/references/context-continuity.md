# 上下文连续性与压缩恢复协议

目标：上下文压缩、换会话或分身释放后，阿极能从已完成状态继续，不重做副作用，不丢未完成分支。复用 Claude 自带的上下文摘要、memory、工作区真实产物和工具回执。不建第二记忆库，不建常驻 memory 代理，不做全量状态文件。

## 何时写恢复包

只在这些情况写或更新：长任务；跨上下文或跨角色交接；多个未完成分支；已发生重要副作用；即将压缩。简单答疑、单步小改、已完成任务不写。可从当前可见上下文直接恢复时，也不重复存档。

## 最小续接包

只记会改变下一步行动的字段：

1. **目标与边界**：用户原始目标、交付物、明确授权和禁止项。用户插话只改变部分目标时，记受影响部分。插话不是取消。
2. **完成**：已实际完成的动作和产物路径，必要时附 hash 或版本。区分计划、已调用、有回执、最终结果。
3. **待办与依赖**：未完成分支、各自下一动作、真实数据依赖、能否并行。独立分支不因另一支阻塞而丢弃。
4. **状态与阻塞**：completed、failed、unknown、cancelled、blocked，以及具体缺的输入、权限或工具。unknown 的提交先查原调用或目标状态，不当作未发生而重发。
5. **来源与结论**：只留支撑决策的结论、关键原始来源、版本或日期、反例或 unknown。长原文用路径和 hash 回读，不复制。
6. **分身状态**：仍在运行的必要分身及其任务。已结束的分支释放。后台分身是否仍在运行，以任务通知或工具回执为准。
7. **唯一下一步**：恢复后先做哪一个动作。不写一串重新计划，不让用户重复已给过的目标。

## 骨架与切片

自己写的大表格或长文档，开头放骨架：每段的标题、一句用途、版本或 hash。续接和派发只带骨架路径加段锚点，不贴正文。

- 锚点用标题名，行号只作提示，段落移动后以标题为准。
- 恢复包的"完成"和"来源与结论"只记骨架路径和段锚点。
- 新上下文先读骨架，再只读当前要改的那一段，其余段不读。
- 改完某段，同一次编辑里更新骨架里的版本或 hash。
- 只适用于自建、格式可控的文档；外部资料和网页仍按先存文件再 grep 处理。

## 压缩前后的动作

- 先依赖 Claude 自带的摘要机制携带这些字段。只有它携带不了必要状态，且任务仍未完成时，才在任务工作区写一份短恢复说明。
- 新上下文先读恢复包和它引用的必要产物。hash 或版本过期时，只回读该引用并更新局部状态，不重扫全部资料。
- 对照真实工具结果恢复：不重复已完成动作；继续所有可做的分支；具体阻塞只停依赖它的分支。
- 用户中途提问先回答，再按原目标续做。只有明确取消或替换才重定向。
- 任务完成后，临时恢复包不自动晋升为长期 memory。要保存可复用知识，必须有真实消费者，并按 memory 规则写成单条事实。

## 方法来源（选择性吸收）

- 完成后记录可复用状态：仅在真实长任务或交接时写最小检查点。
- 大输出先在工具侧处理，只带回摘要和必要字段，引用可回读的路径或 hash。
- 资料蒸馏：提取核心方法、判断标准、适用边界和依据，只把能改变当前决策的部分放入恢复包，保留来源引用，不把摘要冒充原文。

这些来自 Codex 版 5.0 的既有研究结论，此处只落为执行契约，并未重新复核外部项目的最新版本。

## 不做的事

不持续写对话转录；不复制全量聊天或分身思考；不对每条简单消息建 memory；不按 token 阈值强制存档；不增加恢复验收门。
